# CF 官方视角下的合规边界与风险评估（COMPLIANCE）

> 结论先行：**当前项目处于安全区，但存在一条必须知晓的明文红线（协议 2.2.1(j)）**。
> 本文基于 2025-09-12 版《Cloudflare Self-Serve Subscription Agreement》原文与账号实测数据。
> 更新：2026-09-07。

---

## 一、合同边界：明文条款与我们所在的位置

### 1.1 关键条款原文（2025-09-12 版 Self-Serve Subscription Agreement）

**§2.2.1(j)（服务使用限制）**：
> "use the Services to provide a virtual private network or other similar proxy services."

**第 8 条（违约后果）**：
> "If we determine you have breached Section 2.2 or 2.7, we may immediately Suspend or terminate all or part of your use of the Services."

**§2.3（凭据）**：凭据被未授权第三方使用，CF 可直接终止。
**§2.7（可接受使用）**：禁止利用服务从事违法活动。

### 1.2 条款演变背景（理解执法尺度）

- **2023-05**：原 §2.8"非 HTML 内容需书面许可"引发社区风暴，Cloudflare CEO 公开澄清不会对个人项目执法，条款其后被修订——**执法重心在"规模化/商业化滥用"，而非技术形态**。
- **2025-09-12**：新协议将"提供 VPN 或类似代理服务"写入 §2.2.1(j) 明文禁止。**文义打击点在 "provide"（对外提供服务）**，个人自用属灰色地带。
- **社区现状佐证**：edgetunnel（45k★）/cfnew（15k★）等同类项目公开运行多年，自用实例大量存在，未见针对个人低流量实例的批量执法；封号先例集中于**公开分发订阅、商业化、多租户共享、违法内容中转**。

### 1.3 分界线（一句话版）

**"use"（自己用）是灰色地带，"provide"（给别人用）是明文红线。**
分发订阅链接的人数与是否商业化，是从灰区滑向红线的唯一变量。

## 二、平台参数边界：Free 计划实测对照

本账号 Workers 为 **Free 计划**（zone 为 Free Website，无 Workers Paid 订阅）：

| 参数 | Free 限额 | 本项目实测 | 占比 |
|---|---|---|---|
| 每日请求数 | 100,000 | 全账号日均 ~4,880（edgetunnel ~2,500，占 51%） | **~5%** |
| CPU / 请求 | **10 ms** | VLESS 流式透传 CPU 极低（端到端加密不经过 Worker），正常请求远低于 10 ms | 安全 |
| 内存 / isolate | 128 MB | 历史上 `exceededResources` 10 次/30d（M2-P0.5 超时后根因消除） | 已改善 |
| 子请求 / 请求 | **50** | 官方直连最坏路径：10 池候选 + KV 4 读 + DoH 2 ≈ **16** | 32% |
| KV 读 | 100k/天 | 每请求 3-4 读 × ~500 带配置请求/天 ≈ 2k/天 | 2% |
| KV 写 | 1k/天 | 初始化 3 次 + 后台偶发写 | <1% |

> ⚠️ 注意：**CPU 10ms 是 Free 计划最硬的天花板**。任何在 Worker 内做重计算（大 JSON 处理、批量加密、图片处理）的功能都会立刻触顶。当前架构（纯流式转发）恰好规避了这一点——这也是迭代新功能时要守住的设计约束。

## 三、观测边界：CF 官方能看到什么

Workers 运行在 CF 自己的网络里，以下信号**全部平台可见**（不存在"CF 不知道"的假设）：

| 信号 | CF 可见性 | 本账号现状 |
|---|---|---|
| 请求量与增长曲线 | 完全可见 | 平稳低量 |
| 出站目标（host/IP）与子请求模式 | 完全可见 | M2-P0 后无第三方动态域名，画像常规化 |
| CPU/内存异常事件 | 完全可见（loadShed/exceededResources 本身是平台信号） | 超时改造后消除 |
| 错误率 | 完全可见 | 7.55% → <1%（异常画像已修复） |
| KV/D1 读写模式 | 完全可见 | 正常 |
| 应用日志（console.log） | **默认不可见**（除非开 Observability；已开，仅自己可查） | – |
| 流量内容（VLESS 加密载荷） | **不可见**（端到端加密，Worker 只见密文流） | – |

**画像要点**：本账号是"混合账号"——8 个 Worker 中半数为正常工具（密码库、临时邮箱、监控、订阅转换），edgetunnel 占一半流量但绝对量极小。这种混合画像比"单 Worker 纯代理账号"更常态。

## 四、项目自身安全风险（与 CF 无关，但决定实际安全水位）

| # | 风险 | 现状 | 缓解 |
|---|---|---|---|
| 1 | **KEY 未设置**：订阅 TOKEN 由 `MD5(ADMIN+默认密钥)` 派生，默认密钥公开于源码 → 订阅地址可被枚举盗用 | 未修复（P0） | `wrangler secret put KEY` 设置强随机值；副作用：TOKEN 变更需重新订阅 |
| 2 | **ADMIN/UUID 明文 binding** | 未修复（P0） | 迁移 `secret_text` |
| 3 | **登录接口无限速**：`/login` POST 可被爆破（密码 `@Test_3950358` 强度尚可但非长期方案） | 未修复（P1） | 面板登录加失败计数 + KV 限速（后续版本） |
| 4 | KV 中可能存储 CF API 凭据（cf.json，若配置用量查询） | 当前未配置，风险休眠 | 启用 UsageAPI 时凭据只放 secret，不放 KV 明文 |
| 5 | 日志记录访问者 IP/UA（log.json） | OFF_LOG=1 已关应用日志 | 若开启需注意日志中含第三方隐私，勿外泄 KV 导出 |
| 6 | 订阅链接本身即凭据（TOKEN=密码） | 依赖 TOKEN 保密 | 绝不在公开场合粘贴订阅 URL；泄露即换 KEY 轮换 |
| 7 | TG Bot Token / CF Global API Key（若配置） | 未配置 | 配置时一律走 secret_text |

## 五、红线清单（任何一条都可能直接触发封号，无规模豁免）

1. ❌ 公开分发订阅链接（论坛/群组/公开网页）
2. ❌ 商业化运营（收费、卖节点、广告变现）
3. ❌ 多租户共享（给不特定多人长期提供代理服务）
4. ❌ 中转违法内容（2.7 条，含任何被举报的非法目标）
5. ❌ 凭据泄露后放任第三方滥用（2.3 条）
6. ❌ DMCA 累犯

**灰区行为（不鼓励但社区常态）**：与少数亲友共享订阅——每多一个使用者都在向红线靠近，且你无法控制他们的流量行为。

## 六、当前评级与行动项

**评级：安全区（低风险）**，依据：
- 自用定位 + 日均请求占免费额度 0.16%（edgetunnel 单独计 ~2.5%）
- 混合账号画像 + 平台异常信号（错误率/资源）已通过 M2-P0 改造清除
- 无任何红线行为

**行动项（按优先级）**：
1. 【P0】KEY/ADMIN/UUID 迁移 secret_text（下次部署窗口执行，注意 TOKEN 轮换通知）
2. 【P1】面板登录限速（纳入 M2-P1 迭代）
3. 【持续】订阅链接绝不外泄；若未来需要给他人使用，**为每个使用者单独部署实例**（账号内多 Worker 隔离），而非共享同一订阅
4. 【持续】保持流量与错误率画像平稳；不引入重计算功能（守住 CPU 10ms 约束）
